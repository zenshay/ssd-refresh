# Security policy

## Private reports

Do not publish exploit steps, private paths, or sensitive reports in an issue.
Use GitHub private vulnerability reporting if this repository offers it:

1. Open the repository [Security page](https://github.com/zenshay/ssd-refresh/security).
2. Select **Report a vulnerability**, if that button is available.
3. Describe the affected version and a reproduction with synthetic files.

Private reporting is not confirmed as enabled for this repository.
The current configuration check did not establish that the feature is available.
If the button is absent, a private reporting channel is not established here.
Do not post vulnerability details in a public issue as a substitute.
You may request a private channel without disclosing the vulnerability.
This project does not publish a security email address.

Keep original reports on your computer.
Remove user names, file names, full paths, device serial numbers, and secrets from any excerpt.
Do not send full CSV files, disk images, personal files, or full logs.
Use synthetic paths and files for the reproduction.

## Fix and support limits

Report the release version and commit when known.
Maintainers assess reports against the current source.
This project does not promise a response deadline or fixes for every older release.
A security policy does not imply that a release has passed a security audit.

The Windows application is not signed.
Windows and security software may show warnings.
Check the release source. Do not disable security controls to remove warnings.

Read the [security scope](docs/security.md) before storage operations.
Use [Support](SUPPORT.md) for ordinary problems without security details.
